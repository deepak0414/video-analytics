## How to run

These fixtures live in their own workdir (the shared `.va-shots` holds the A-EV
videos). The harness auto-skips fixtures whose video is not in `GOLDEN_WORKDIR`, so the
two sets run independently:

```bash
# ingest (once): each clip with the security profile + real models
VA_CONFIG_DIR=run-claude/config .venv/bin/va --workdir .va-nvr ingest \
    /home/debug/nvr-clips-2026-08-01/clip_00_cam1.mp4 --profile security   # ×22

# run
RUN_GOLDEN=1 VA_CONFIG_DIR=run-claude/config GOLDEN_WORKDIR=.va-nvr \
    .venv/bin/pytest tests/test_golden_queries.py -m golden -q
```

## Calibration

`default_min_score` keeps the `.va-shots`-calibrated 0.10 — it separates cleanly here
too (true-neg ≤0.048, true-pos ≥0.114; per-query measurements in the yaml comments;
a `-s` run reprints the calibration table). Full run 2026-08-04 against this exact
fixture set: **17 passed / 8 xfailed / 0 failed** (25 cases), and the `.va-shots`
A-EV set is untouched (85 passed / 1 xfailed, the 25 NVR cases auto-skipping).

Two calibration deltas vs the spike scorecard (which ran the detector STANDALONE at
2 fps): the in-ingest detector misses the clip-02 kids entirely (spike found
person×4 + bicycle) and does NOT reproduce the clip-15 person×7 false positive.
In-ingest and standalone detection are different regimes — fixtures assert the
in-ingest one, because that is what `va objects` serves.
