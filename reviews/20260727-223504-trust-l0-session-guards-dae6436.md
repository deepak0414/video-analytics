## Findings

**1. (major) `.claude/hooks/bash_guard.py:39` — `WRITE_VERBS` matches only sed's *short* `-i`, so `sed --in-place` walks past every protected-artifact and machinery rule.** The alternation ends with `\bsed\b[^|;&\n]*\s-[a-zA-Z]*i[a-zA-Z]*\b`, which requires a `-i`-containing cluster; GNU sed's long form starts `--`, so `[a-zA-Z]*` can never reach the `i`. Verified against the committed guard (control in parentheses): `sed --in-place s/request_changes/approve/ reviews/x.md` → exit 0 (`sed -i …` → 2), `sed --in-place s/x/y/ .githooks/pre-push` → 0 (`sed -i` → 2), `sed --in-place s/exit_2/exit_0/ .claude/hooks/bash_guard.py` → 0, `sed --in-place s/x/y/ .git/.stop-gate-green` → 0. `install /tmp/forged.md reviews/x.md` → 0 as well (coreutils write verb, same class as the listed `cp`). This is exactly the attack round 5 confirmed and fixed for the short flag: the current round's ledger is still untracked, so the append-only gates (`--diff-filter=MDR`, `.githooks/pre-push:57`) never see it as modified, and a one-line `sed --in-place` flips its verdict to `approve` before the human reads the digest.

**2. (major) `.claude/hooks/path_guard.py:25` — `.git/config` is unprotected, so a single Write disables every git-side gate.** `ALWAYS_PROTECTED` covers `.git/.review-approved` and `.git/.stop-gate-green` — so the design already treats `.git/*` as reachable by file tools — but not `.git/config`, which is where `scripts/setup-hooks.sh` stores `core.hooksPath = .githooks`. Verified: path_guard exits 0 for `.git/config` and `.git/hooks/pre-commit` (and 2 for `reviews/x.md`, `.venv/bin/pytest`). Writing `[core]\n\thooksPath = /dev/null` into `.git/config` turns off pre-commit, the post-commit reviewer, and pre-push in one edit — the same outcome the settings deny-list entry `Bash(git config core.hooksPath*)` and bash_guard's `core.hooksPath` rule exist to prevent, reached through the tool path those rules don't see.

**3. (major) `.claude/hooks/bash_guard.py:121` — force-push detection only inspects explicit refspecs, so `--all` and `--mirror` rewrite remote main without ever naming it.** With no refspec, `refspecs` is empty and the code falls through to resolving the *current* checkout, which on a feature branch is not main — but `--all` pushes every local branch and `--mirror` pushes every ref and deletes remote refs missing locally. Verified allowed from a non-main checkout: `git push --force --all origin`, `git push --all --force origin`, `git push --mirror origin` (control `git push --force origin main` → blocked). Nothing catches it downstream: `.githooks/pre-push` has no force logic at all, and for `--mirror`'s deletions the loop hits `[ "$local_sha" = "$zero" ] && continue` (`.githooks/pre-push:10`), so remote branch deletion is completely ungated. Validation-matrix rows 42/47 claim this invariant is closed.

**4. (major) `.claude/hooks/stop_gate.sh:19` — the cache key omits `config/`, which the offline suite reads, so a config edit yields a stale green.** The key hashes `src tests pyproject.toml .claude .githooks scripts`; `config/roles.yaml` is the default config dir (`src/va/configuration.py:19-20`) and `tests/test_config.py:5` asserts on its contents (`rc.model == "hash"`, `active_profile == "dgx-spark"`). An agent switching a backend in `config/roles.yaml` — a routine action this repo documents — turns the suite red, but the cache key is unchanged, so the Stop gate hits the cached green and lets the turn end without running pytest. This is the same stale-green class as the round-3 major that added the machinery paths (matrix row 45); the fix there enumerated paths rather than covering everything the suite reads.

**5. (minor) `.guard-override:1` — the maintenance sentinel is still live in the working tree** (created 21:30, untracked/gitignored). While it exists, every session on this machine runs with the machinery-write rules and the `core.hooksPath` rule relaxed — `.githooks/`, `.claude/`, and the trust scripts are agent-writable. The previous ledger noted this and it has not been cleared; it should be removed before finalize.

None of findings 1-4 have test coverage: `BLOCKED_COMMANDS` has `sed -i` but no long form, no `--all`/`--mirror` push, and `BLOCKED_PATHS` has no `.git/config`. That is the same "tables mirror the regexes, not the invariants" root cause the plan records as addressed in round 1.
