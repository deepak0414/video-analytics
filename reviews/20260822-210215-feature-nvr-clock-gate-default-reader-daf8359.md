### MINOR 1 — the fail-open guarantee has an undocumented blind spot: consistent date-digit *substitution*
`src/va/sources/ocr_clock.py:107`. The `\d{2}` rule closes dropped digits and the 12 h+ tolerance closes time-field misreads, but a consistent *substitution* in the day/month field (3↔8, 1↔7, 0↔8 — the classic OCR confusions) produces a confident, agreeing, multi-day skew on GOOD footage by exactly the mechanism the code documents for dropped digits (near-identical head pixels → the same error on every sample). Scenario: overlay `08-03-2026` read as `08-08-2026` on all 8 head samples → skew 5 d > tolerance → no aligned tail → reject; phase 1 retries and phase 2 OCR the same pixels → `RuntimeError` → `watch.py:222-229` holds the camera's watermark and aborts its pass, retrying that episode first next cycle — a camera wedge until the window ages off the ring. 0/238 observed on `.va-24h`, so the rate is low, but CLAUDE.md/COORDINATION state "never a false-reject of good footage on OCR noise" / "ZERO good-footage false-rejects" as a guarantee. Safe path: document this as a residual (the guarantee covers dropped digits and time-field misreads only), and consider a body-consistency cross-check before a whole-head reject (OCR one body frame: a misread identical in head and body is noise; a head that differs from its own body is contamination).

### MINOR 2 — the validation script's "whole-clip-wrong-week" bucket conflates verified-bad with unverifiable
`scripts/validate_clock_gate_va24h.py:131`. `_body_is_aligned` returns False both when the body reads wrong-week AND when the body has no parseable Role-10 row, so the reported "3 whole-clip-wrong-week" (and the "ZERO false-rejects" claim that rests on it) includes clips whose body simply didn't OCR. Scenario: a 352x240 sub-stream clip whose overlay is illegible at that resolution is classified as a genuine wrong-week catch with no evidence either way. Safe path: three buckets (body-aligned / body-off / body-unreadable) and state the unreadable count in the CLAUDE.md/COORDINATION claim.

### MINOR 3 — the tolerance value is stated three different ways
`CLAUDE.md:117` and COORDINATION.md say `CLOCK_OCR_TOL_S=12 h`; the code (`src/va/sources/nvr.py:159`) is 12 h + 300 s by design; the commit body says "CLOCK_OCR_TOL_S=600s" (stale from an earlier round). Scenario: an operator reading the docs concludes a 12 h + 40 s skew rejects (it doesn't), and the finalize amend carries a wrong number into history. Safe path: "12 h + 5 min margin" in both docs; fix the commit body at finalize.
