## Full review

Review complete — static-only (I did not run the test suite; all verification is by reading). Scope: `origin/main..HEAD` = two commits, the `va reprocess` dry-run planner (finalized, `fa489c3`) and the RPRC-1a executor for `text_embedder` (provisional `need_agent_review:`, `dbf89b1`).

**What I verified and what dissolved:** the scope-XOR and non-done-video guards in `plan_reprocess` are correct (truth-tabled, and each has a test); `ProvenanceStore.record/get`, `stale_report`, `lookup_video`, and `current_run_id` are all called consistently with their real signatures; the rows-first/provenance-second ordering is genuinely implemented and tested for both the failure path (`test_execute_failure_leaves_role_stale`) and the skip path; the replaced gating test (`test_cli_execution_is_gated_off` → `test_cli_executes_supported_and_skips_unsupported`) tracks an intentional behavior change, not a weakened test, and `test_cli_dry_run_mutates_nothing` still pins the read-only path; the wrong-`VA_CONFIG_DIR` foot-gun (executing under the stub config would rebuild real text vectors with stub output) is covered by the designed guard — the config header prints before execution and TAG-3's shard tag makes the result non-silent, so I did not file it; COORDINATION.md logs the write path with the concurrency note for the web agent, honoring the prior entry's promised heads-up; CLAUDE.md's command list was updated in the same change.

**Four findings survived:**

1. **Major — stale safety-relevant help on a write path** (`src/va/cli.py:443`, `:452`, plus `src/va/pipeline/reprocess.py:5`). The subcommand help still says "dry-run only" and `--dry-run`'s help says "execution is not implemented yet", while running without `--dry-run` now rebuilds the `text_vectors` shard and restamps provenance. One commit ago the no-`--dry-run` form printed the plan and *refused* — a user who read `--help` or used that version will run `va reprocess --all-stale` expecting a refusal and mutate a shared workdir instead. The `reprocess.py` module docstring makes the same false claim in the file that implements the executor. Safe path: update all three strings in this change (e.g. "re-run stale roles in place (text_embedder; others skipped → `va reingest`)"; `--dry-run`: "plan only, no changes").

2. **Minor — a `None` from backfill is restamped as success** (`src/va/pipeline/reprocess.py:76`). `backfill_text_index` returns `None` when its `lookup_video` fails (video removed between plan and execute, or a stale plan from a library caller — the audience COORDINATION.md explicitly invites). `return n or 0` converts that to a 0-row "success", so `execute_reprocess` restamps provenance for a video whose shard was never rebuilt — recreating a provenance row for a removed video and breaking the advertised "never falsely current" invariant. Safe path: `if n is None: raise ValueError(f"video {video_id} not found")` so the executor routes it to `failed`.

3. **Minor — the skip pointer drops `--fps`** (`src/va/cli.py:287`). The message says ``run `va reingest {vid}` `` with no `--fps`, while `va stale`'s remedy and the plan doc both insist the reingest pointer carry `--fps <recorded>` because reingest defaults to 1.0 and silently changes the frame density Roles 2/5/6/7 saw — and the previous commit's refusal message did include `--fps <N>`. A user copy-pasting the skip line mid-model-switch re-ingests at the wrong density. Safe path: the plan rows in scope carry `recorded_fps`; append `--fps {fps}` when known.

4. **Minor — per-role config reload can stamp a fingerprint that drifted from what ran** (`src/va/pipeline/reprocess.py:126`). `role_fingerprint(r)` does a fresh `load_config()` per (video, role), and the embedder inside `backfill_text_index` loads its own config too; a config edit mid-batch can stamp the new config's fingerprint on rows the old config's embedder just wrote — a missed stale, the failure mode PROV-3 explicitly pinned a single launch-time config to prevent (and `stale_report` snapshots once for the same reason). Safe path: `cfg = load_config()` once at the top of `execute_reprocess` and pass it to every `role_fingerprint(r, cfg)` call.

Verdict: **request_changes** — finding 1 is major (wrong safety documentation on a newly-mutating command); all four fixes are small and local.
