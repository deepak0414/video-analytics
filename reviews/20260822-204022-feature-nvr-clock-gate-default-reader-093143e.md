### MINOR 1 — "NON-DESTRUCTIVE" overclaims what a clock-gated `va reingest` preserves
`COORDINATION.md:932`, `CLAUDE.md:181` (mechanism: `src/va/pipeline/manage.py:126-145` + `src/va/sources/nvr.py:321-332`). `reingest_video` runs `remove_video(keep_media=True)` — deleting every role table row, the catalog row, and the whole per-video dir (`vectors.npz`, `appearance.npz`, keyframes) — BEFORE `ingest → fetch()` re-verifies the parked clip. For one of the ~22 `.va-24h` clips, the re-verify rejects, the re-pull fails, and the restore puts back only the media bytes; the video ends as a `failed` row with no derived data until the operator reruns with `VA_NVR_CLOCK_GATE=off`. Scenario: `va reingest <one of the 22>` on the primary backfill workdir (e.g. after a model bump) → 9 roles' outputs gone, row `failed`, one more gate-off command needed to get back to where an ordinary reingest would have landed. Recoverable, hence minor — but the docs present it as safe. **Safe path:** either word it precisely ("the media bytes are restored; the role outputs are dropped and the row reads `failed` until reingested with the gate off"), or pre-flight the verification for `nvr_recorded` clips in `reingest_video` BEFORE `remove_video` (mirroring the quarantine refusal that already sits there), so the data survives the refusal.

### MINOR 2 — the `--real` validation's "22 all genuine wrong-week heads, ZERO false-rejects" isn't auditable from the script's own output
`scripts/validate_clock_gate_va24h.py:174` vs its docstring at `:32` ("listing any reject with its head OCR so a true-positive can be told from a false-reject"): `run_real` records `(vid, kind, path)` with no head readings, and `_body_is_aligned` classifies on ANY single aligned body row — so a reject whose head is a consistent date-field OCR misread (two-digit, so it survives the `\d{2}` fix) over a body with one correctly-read row would print as "body-aligned(RECOVERABLE)" identically to a genuine 2–3 s wrong-week head. The 08-03→08-10 transition evidence cited in the dispute record was gathered ad hoc, not by the shipped script. Scenario: a future run on a different workdir reports N "body-aligned" rejects and nobody can tell OCR noise from contamination without re-instrumenting. **Safe path:** in `--real` mode, append each reject's head readings (overlay text or `(t, skew_s)` pairs) to the listing, so the true-positive claim is reproducible from the script alone.
