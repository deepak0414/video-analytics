## Findings

**1. major — `src/va/pipeline/reprocess.py:332` — the reprocessor runs the tracker and writes `object_tracks` unconditionally, ignoring a profile that disables `object_tracker` while keeping the detector.** `object_tracker` is independently gateable (`configuration.py:125-128`), and ingest explicitly supports the tracker-disabled/detector-enabled combination: it stores *untracked* detections (`track_id` NULL) and purges tracks, calling this the "no-live-rows invariant for a disabled role" (`ingest.py:608-628`). The executor's disabled-role skip only filters roles *in `stale_roles`*, so with such a profile a stale `object_detector` flows into `_reprocess_object_detector`, which calls `get_object_tracker(cfg).track(...)` and `replace_tracks(...)` regardless — regenerating exactly the data the profile forbids (the executor's own comment names this hazard). The forbidden rows are unstamped-and-disabled, so `va stale` excludes them forever (no convergence), and `va count` starts answering from tracker output the profile turned off. Safe path: mirror ingest inside the reprocessor — when `cfg.role("object_tracker")` is disabled, write the flat untracked detections and `replace_tracks(video.id, [])` — and add a test for this combination.

**2. minor — `src/va/pipeline/reprocess.py:340` — reprocess strands the ingest-era appearance shard and silently downgrades appearance capture.** Ingest captures one appearance embedding per track into `appearance.npz` with payloads keyed by track id; the reprocessor deletes all track rows, writes new tracks with `appearance_ref` NULL, and leaves the old shard on disk with every payload referencing a now-deleted track id. Ingest's own retry path treats exactly this staleness as something to clean up (`ingest.py:505-521` deletes the stale shard and nulls dangling refs). The docstring acknowledges the NULL refs but not the orphaned shard. Scenario: a reprocessed video carries an `appearance.npz` full of dangling track references that Role-12 ReID (the shard's stated consumer) would surface as phantom matches. Safe path: delete the video's `appearance` shard files alongside `replace_tracks`, or re-capture appearance in the same pass.

**3. minor — `COORDINATION.md` (no entry in this range) — the new reprocess write path is not logged in the append-only coordination log.** Every previously wired reprocess role got a dated entry with explicit "for the web agent" implications (RPRC-1a/1b/1c at `COORDINATION.md:326-370`); this change extends the same shared surface — `va reprocess` can now replace `object_detections`/`object_tracks` under a live `va serve` answering `va objects`/`va count` — with no entry. Safe path: add the RPRC-style entry (wired role, tracker rebuilt in-pass, appearance behavior) before finalize.

**4. minor — `src/va/pipeline/reprocess.py:355` (and `:370`) — stale comments contradict the code they sit next to.** The `_SATISFIES` block comment still says "One edge is active for in-place reprocess" and lists `R5->R6` among the edges whose roles "aren't in-place reprocessable", directly above the new `object_detector -> object_tracker` entry; `_dependency_ordered`'s docstring repeats "one active edge today". Scenario: the next agent extending `_SATISFIES` trusts the prose over the dict. Safe path: update both comments in this change.
