## Findings

**1. MAJOR — heredoc bodies false-block the loop guard: the exact regression the round-5 ledger predicted, shipped without the test it demanded** (`.claude/hooks/bash_guard.py:364`).
The round-5 review (`reviews/20260728-222045-trust-l4-compounding-7216217.md`) fixed the multi-line bypass but warned verbatim: "naively appending `\n` tokens will false-block heredocs quoting a loop — both cases need tests." HEAD appended the newline tokens (line 366) with no heredoc handling and no heredoc test. Verified against the committed guard:

```
cat > watch.sh <<'EOF'
until ! pgrep -f portscan.py; do sleep 5; done
EOF
```
is **BLOCKED**. The heredoc body is data being written to a file; the resulting `bash watch.sh` process has cmdline `bash watch.sh` — the loop inside it genuinely cannot self-observe and is in fact the *correct workaround* the guard should steer toward. `ssh host bash <<'EOF' …` (loop executes remotely, where no local cmdline holds the pattern) is likewise false-blocked. This re-introduces the false-block class CLAUDE.md's own lesson records ("Prose is not an action — … 'until' inside a heredoc string"), and the repo's stated principle is that every false block pushes toward workarounds. The ALLOWED fixture list covers a `#`-comment but no heredoc.

**2. minor — the most natural backgrounded-watcher spelling bypasses the guard** (`bash_guard.py:368`). `nohup bash -c 'until ! pgrep -f portscan.py; do sleep 5; done' &` and `bash -lc '…'` are **allowed** (verified): the quoted loop is a single shlex token, never equal to `until`. Yet this loop *does* self-observe — the pattern sits on the `bash -c` process's own cmdline — and backgrounding via `bash -c` is a realistic accidental spelling, not evasion. The guard header disclaims proof-level coverage, but the core blocked case escapes in a common shape with zero test coverage.

**3. minor — subshell parens in the condition disable the rule** (`bash_guard.py:404`). `until ! (pgrep -f portscan.py); do sleep 5; done` is **allowed** (verified): `(` becomes the stage's first token, `command_name` returns `"("`, and neither the pgrep branch nor `_has_ps` fires. Same self-observing hang, one pair of parentheses away.

**4. minor — `--invert-match` long form isn't recognized as the self-exclusion idiom** (`bash_guard.py:408`). `until ! ps aux | grep '[p]ortscan' | grep --invert-match grep; do sleep 5; done` is **false-blocked** with pattern `'grep'` (verified) while the identical `-v` spelling is allowed — the same long/short-spelling asymmetry class as round 2's `pgrep --full` finding.
