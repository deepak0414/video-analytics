## Findings

**1. minor — `src/va/pipeline/ask.py:227`: the trace event is unconditionally named `"ran"`, so every skipped sweep is recorded in the traceability ledger as a deep scan that ran.**

`trace("deep_scan", "ran", next((n for n in evidence.notes if "deep-scan" in n), "deep scan"))` fires whenever `plan.needs_deep_scan` is true, including the two new skip paths. Before this change the only skip cause was "no target video resolvable" (rare); the profile veto makes it the *permanent* state for every security-profile video, so any counting ask on NVR footage now writes a `deep_scan / ran` step. Nothing keys on the action string today (I grepped — the only occurrence is this line), and the detail text does say "skipped", so this is a label-vs-fact mismatch in an audit surface, not wrong output. Safe path: pick the action from the outcome, e.g. `"ran" if any(i.modality == "deep_scan_count" for i in evidence.items) else "skipped"`.
