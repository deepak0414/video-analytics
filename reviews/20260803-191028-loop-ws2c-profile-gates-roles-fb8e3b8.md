## Review — round 7 of `loop/ws2c-profile-gates-roles` (HEAD `fb8e3b8`)

**Verdict: request_changes** — one major finding (verified by live reproduction), two minors.

**What I verified first:** both round-6 minors are genuinely fixed with real tests. Non-bool `enabled:` is now rejected at overlay load with a named error (`test_non_bool_enabled_raises`, covering both the quoted-string and null shapes), and a role that ran before its profile was edited to disable it now reads stale (`test_role_disabled_after_it_ran_reads_stale`) with CLAUDE.md updated to match. The WS2.c done-conditions hold (security → 0 transcript rows with retry-purge, vocab override drives real stub detections, generic byte-identical), record==reality is consistent across ingest/stale/reprocess pins, test doubles were widened per the CLAUDE.md lesson without weakening assertions, and I ran the full offline suite: **563 passed / 2 skipped**.

### Findings

**1. major — `src/va/pipeline/reprocess.py:358` — `execute_reprocess` re-runs a role the video's footage profile disables, restamps it, and the video immediately reads stale again: the documented batch remedy never converges and actively violates the profile's gating promise.**

This is the direct interaction of the round-6 fix ("stamped-and-disabled reads stale") with the reprocess path, and I reproduced it end-to-end: ingest under profile `evolving` (all roles on) → edit the profile to `vlm_captioner: {enabled: false}` → `stale_report` correctly flags `vlm_captioner` → `execute_reprocess(plan_reprocess(all_stale=True))` returns `reprocessed: [(…, 'vlm_captioner', 1)]` — it **re-captioned** via `_REPROCESSORS` (the registry getter ignores `enabled`), rebuilt the text index with those captions, and restamped provenance → `stale_report` flags `vlm_captioner` again. So `va reprocess --all-stale --yes` (the documented remedy in CLAUDE.md) runs the heavy VLM role the profile says must not run, regenerates rows the profile says shouldn't exist (and marks `text_embedder` satisfied off them via `_SATISFIES`), and loops forever — every subsequent run redoes the work while reporting success. The non-reprocessable gateable roles (STT/OCR/actions/detector) escape only accidentally, by routing to `skipped → va reingest`, which does converge. Safe path: in `execute_reprocess` (or `plan_reprocess`), check `cfg.role(r).enabled` — with the `GATE_DEPENDENTS` closure — against the item's pinned per-profile config, and route a disabled role to `skipped` with a "profile disables this role — `va reingest` purges its rows" message instead of rebuilding; add a test mirroring `test_role_disabled_after_it_ran_reads_stale` that runs reprocess and asserts convergence.

**2. minor — `COORDINATION.md:419` — the append-only log's latest entry describes the superseded round-6 staleness semantics ("profile-DISABLED roles are excluded from staleness, not reported forever-stale") and doesn't record this round's shared-surface changes.**

At HEAD, disabled roles are excluded **only while unstamped** — stamped-and-disabled now reads stale, and a non-bool `enabled:` in a footage yaml now raises `ValueError` at `load_config` (previously tolerated). An agent reading the log will build against the old contract: e.g. the web agent treats a disabled role's staleness as impossible, or writes a profile with `enabled: "false"` expecting the old lenient load. The evidence line ("555 passed") also predates the final tree (563). Safe path: append one corrective entry logging the two behavior changes (the log is append-only, so a new entry, not an edit).

**3. minor — `src/va/pipeline/ingest.py:415` — the tracker's disabled-gate is short-circuited away when a video decodes zero frames, so `object_tracker` gets provenance-stamped despite the profile disabling it, which under the new stamped-and-disabled rule reads permanently stale with no converging remedy.**

`if det_ok and frames_dets and not _enabled("object_tracker")` never calls `_enabled` (whose side effect registers the skip) when `frames_dets` is empty — reachable when the detector loads but the media yields no sampled frames (ingest, unlike `reindex_visual`, has no zero-frame guard and still marks `done`). The tracker lands in neither `failed` nor `skipped`, is stamped, and — post-round-7 — reads stale forever; `va reingest` repeats the identical path. Round 6 dissolved this stamp as harmless, but the new staleness rule un-dissolves it. Safe path: evaluate the tracker gate unconditionally when the detector gate ran (e.g. `tracker_on = _enabled("object_tracker")` next to the detector check, mirroring `diarizer_on`), so the skip is registered regardless of frame count.

No contract breaks otherwise (schema v3 migration is present and tested; stale rows' new `profile`/`source_type` keys are additive with a fallback for old rows), no hardcoded content (the security vocab lives in the profile yaml, cited to plan §3.2), no test weakening (the reprocess pin test got stronger — it now asserts memoization), and all new flags/keys are documented. Commit subjects are provisional `need_agent_review:` and exempt from the clarity rule.
