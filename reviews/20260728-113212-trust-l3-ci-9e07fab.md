## Summary

This range ships WT.5–WT.7 of the trust plan: two GitHub workflows (offline tests, PR-body/label gates), the critical-paths checker + table, the PR template, `/verify`, six new unit tests, and plan-doc as-built sync. The shell scripting is unusually careful (the fail-open `set -e` trap and the `&&`-as-last-command trap were both caught and documented), the new tests are real, and I chased several suspicions that dissolved on verification — the `CpRepo.__truediv__` staticmethod fixture works (special-method lookup doesn't bind staticmethods, so the lambda receives exactly one arg), the `golden` marker is registered in `pyproject.toml`, `critical_paths.txt` ends with a newline, and the three-dot diff against `base.sha` with `fetch-depth: 0` is sound.

One major finding survives, plus four minors:

**Major — the label gate's core premise is falsifiable by an agent.** `scripts/critical_paths.txt:11` and WT.7's "Done when" both assert that `bash_guard.py` blocks agents from applying `human-reviewed`/`golden-verified` via `gh`. The guard only matches `gh pr edit/review` (`bash_guard.py:314-323`); I verified it has zero coverage of `gh issue edit N --add-label human-reviewed` (PRs are issues — this works on a PR) and `gh api repos/…/issues/N/labels`. Either spelling lets an agent self-attest human review and turn the `critical-paths` check green. The guard file is out of this range, but the gate whose trust rests on that claim — and the claim itself — are in it. The repo's own hardening history treats each missed spelling as a round-major.

**Minors:**
- `check_critical_paths.sh:25` — `set -o pipefail` + `grep -qF` early-exit: on a changed-file list larger than the pipe buffer (~64KB, roughly 1,500+ files) where the pattern matches early, `printf` dies of SIGPIPE (141), the pipeline reads as non-match, and a touched critical path silently needs no label — a residual fail-open in a script whose as-built notes claim fail-open was eliminated (matrix row 79).
- `check_critical_paths.sh:25` — matching is unanchored substring, though the table header says "path prefix": `web/scripts/foo.js` or `myconfig/x.yaml` (contains `config/`) would demand labels spuriously. Fails closed, so friction only.
- `workflow-trust-plan.md:1567` — the WT.6 template block is a botched edit: the entire old template remains appended after the new one, with contradictory stale text ("pre-push writes it" vs the shipped "post-commit writes it"), in a doc that promises verbatim file contents.
- No COORDINATION.md entry for this slice, breaking the convention every prior trust slice followed (entries at COORDINATION.md:220-236). Commits are `wip:`, so this can still land before finalization.
