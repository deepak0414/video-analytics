## Review summary

This commit lands the Qwen3-VL reasoner experiment: a new adapter subclassing `QwenReasoner` (overriding only model construction), an additive registry branch correctly ordered before the generic `qwen` prefix (with an offline test proving the ordering), a new `run-qwen3vl/config` dir that is byte-identical to `run-siglip` except for the reasoner selection, and thorough documentation. I verified the config-merge path (`configuration.py` folds the per-model `dtype: bfloat16` over the profile-level `float16` — the adapter receives the right value) and that the dtype-honoring claim is corroborated by the ~45 GB bf16 RSS in the validated run.

Two minor findings survived verification:

1. **Cache key omits dtype** (`qwen3vl_inproc.py:41`): the adapter newly honors a `dtype` knob, but the ModelManager key is `qwen3vl::{weights}::{device}` — a second construction in the same process with a different dtype silently returns the first-loaded model at the wrong dtype. Low practical risk today (config loads once per process), but the knob's contract ("honored") is only true for the first load. Safe path: include `dtype_name` in the cache key.

2. **The loud-failure dtype-validation branch has zero coverage and can't get any as written** (`qwen3vl_inproc.py:63-70`): the `ValueError` for a typo'd dtype sits inside `_build`, after `import torch`, so the offline suite (no torch required) can never exercise it, and the failure surfaces only at first model build rather than at adapter construction. Safe path: validate `self.dtype_name` against the allowed names in `__init__` (no torch needed for the name check) and add an offline unit test that a bad dtype raises.

Several suspicions dissolved on inspection and are not reported: the test's monkeypatching works because both adapter modules import without torch at module level; the dead `claude-code: timeout_seconds` profile entry is harmless; the experiment doc's stale "still uncommitted" note is superseded in-document by the dated Outcome section; the deprecated `torch_dtype` kwarg works on the pinned-floor stack and would fail loudly, not silently, if a future major release dropped it.
