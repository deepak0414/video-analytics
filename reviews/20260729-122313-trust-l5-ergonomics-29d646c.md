## Findings

**1. MAJOR — `tests/test_trust_hooks.py:632` — the push-gate half of `test_disputes_only_branch_is_not_treated_as_docs` is a tautology that cannot fail.**
The assertion is `("skipping re-review" in push.stderr) or (len(r.ledgers()) >= before)`, where `before = len(r.ledgers())` was captured immediately prior and ledger files are never deleted — so the second disjunct is always true and the assertion passes no matter what pre-push does. Plant-the-defect check (WT.12 item 5, codified in this same commit): revert pre-push's regex to the old `'^(\.claude/|\.githooks/|\.github/|scripts/)|^CLAUDE\.md$'` and this test stays green — the disputes-only branch silently regains the docs-only skip at the backstop, which is the exact end state round 3 rated major. The docstring claims "regression for the never-inert list in all three hooks," but only post-commit's copy is genuinely tested (the first half is a real plant-the-defect test); pre-push's copy is covered by decoration, and commit-msg's copy (which decides whether a plain-subject disputes-only commit needs approval) has no test at all. The adjacent `r.git("update-ref", "-d", "refs/heads/nonexistent")` "no-op, keeps intent clear" line is dead code that clarifies nothing. Note the push in this test is doomed to fail at Gate 3 regardless (the branch tip has a provisional `need_agent_review` subject), so a real pre-push assertion needs either a finalized commit or an explicit assertion on the "skipping re-review" / review-fired evidence alone, verified red against the old regex. This is precisely the repo's own recorded lesson: "a regression test that cannot reproduce the original failure is decoration."

**2. MINOR — `.githooks/pre-commit:27` (rule 2c) and `.githooks/pre-push:62` (Gate 2b) — a fifth mechanism was not taught about the new writable surface: committed dispute files are append-only, contradicting the documented contract that disputes are agent-writable.**
Both append-only rules match all of `reviews/` with `--diff-filter=MDR` / `grep '^[MDR]'`. Scenario: the agent commits a dispute in the provisional commit (Add — fine), the re-review judges the dispute's evidence insufficient, and the agent edits the same dispute file to strengthen it and amends — the staged diff vs HEAD shows `M reviews/disputes/<file>.md`, and pre-commit fails with "reviews/ ledgers are append-only … ALLOW_LEDGER_EDIT=1", a human-only override. Meanwhile the session guards and `reviews/disputes/README.md` ("Only `reviews/disputes/<file>` is writable by an agent") say the file is editable — the agent can edit it in the worktree but can never commit the edit. This is the same defect class as this PR's round-2 and round-3 majors (the as-built note itself concludes "one change per mechanism that reasons about that area" and counts four; the append-only rules are the fifth). Fail direction is closed, hence minor — but per WT.12 item 6, a false block that points at a human-only override is exactly the pressure toward workarounds the guards exist to prevent. Either exempt `reviews/disputes/` from 2c/Gate-2b (with a test), or document disputes as append-only-once-committed and make the README/plan say so.

Dismissed after verification (not reported): substring over-match of the linker rule on paths like `my-reviews/disputes-notes` (contrived, fail-closed); `cp`/`mv` naming the `reviews/disputes` directory itself being blocked (conservative, per-file writes work); `norm("")` → `"."` (inert); cwd-relative evasions of bash_guard (pre-existing, dismissed in round 5); `mv`-a-symlink-into-disputes (the write through the link is still caught by realpath at write time).
