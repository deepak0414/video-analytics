## Full review

Review complete. This is round 3 of this branch; I verified all four round-2 findings were genuinely fixed in the amended HEAD (01d69ef): the `_enabled()` gate now tolerates a roles.yaml that omits roles (with a regression test that reproduces the minimal-config ingest), `object_tracker: {enabled: false}` is honored, the vocab override is proven end-to-end (color-class profile drives stub detections down to the stored `object_class` rows), and the embedder-override caveat is documented in CLAUDE.md plus the loop backlog. The suite is genuinely green — I ran it: 555 passed / 2 skipped, matching COORDINATION's claim. Schema v3 is migrated and logged; stale/reprocess/text-backfill all resolve each video's recorded profile via `config_for()`; documentation and COORDINATION parity are thorough. The WS2.c "Done when" (security-profile ingest → 0 transcript rows + overridden vocab; generic unchanged) is met with real tests.

What remains — four minors, no majors:

**1. The tracker-disabled branch is a new code path with zero coverage** (`src/va/pipeline/ingest.py:397-411`). The round-2 tracker finding was fixed in code, but no test exercises `object_tracker: {enabled: false}` — the branch that flattens detections, stores them untracked, and purges prior tracks has never executed. Per the repo's own lesson, a fix without a test that fails on the old code is decoration: a typo in the `model_copy(update=...)` dict or a regression re-coupling the tracker to the detector would leave the suite green. Safe path: one ingest test with a tracker-disabling profile asserting detections > 0, tracks == 0, and `object_tracker` unstamped.

**2. Disabled-role purge writes can abort the ingest** (`src/va/pipeline/ingest.py:281`, and the same pattern at 287, 306, 353, and the 397 branch). Every *enabled* best-effort role wraps its store writes in the role's try/except → `failed.add(...)`; the new skip-path purges (`replace_*(video.id, [])`) are bare. A store error there — e.g. writer-lock contention from the web layer or another session against the same catalog.db — escapes to the outer handler and marks the whole video failed, which is exactly the "best-effort role able to abort ingest" class the repo forbids. Safe path: wrap each purge in the same catch-log-continue pattern (a failed purge leaves the role in `failed`, unstamped — the safe stale direction).

**3. `va stale` honors `enabled: false` on core roles that ingest ignores** (`src/va/pipeline/stale.py:48`). The exclusion set is computed over ALL roles, but ingest never gates scene_detector/visual_embedder/text_embedder — they run and get stamped regardless. A profile that (mis)sets `visual_embedder: {enabled: false}` therefore produces videos whose embedder ran and was stamped, yet is permanently excluded from staleness — a later embedder model change is a MISSED stale, the one direction §6-b forbids. Requires a misconfigured profile, hence minor. Safe path: restrict the exclusion to the ingest-gateable role set, or reject `enabled: false` on core roles at load time.

**4. The shipped example in generic.yaml demonstrates a key nothing reads** (`config/profiles/footage/generic.yaml:14`, replicated in all four config dirs). The example shows `object_detector: params: vocab: [...]`, but the actual vocab keys are `classes:` (detector) / `actions:` (recognizer) — `params.vocab` deep-merges silently and no code reads it. A profile author following the file's own example writes a silent no-op override, the exact silent-misconfiguration foot-gun the layer's other validation (unknown role names raise) works hard to prevent. Safe path: fix the example to `classes:` in all four copies.

Commit subjects are all provisional `need_agent_review:` — exempt from the clarity rule. No contract breaks: the schema change is migrated, and every shared-surface change is logged in COORDINATION.md with the web-agent behavior note.

Verdict: **approve** — nothing critical or major; the four minors above are cleanup-pass material (the first two land in the same file and pattern).
