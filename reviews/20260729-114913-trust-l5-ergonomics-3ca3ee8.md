## Review — `origin/main..HEAD` (commit `7907a02`)

Everything below is judged against the current commit; the `/commit` doc is no longer in the range, so I discarded what I had on it.

**Prior round's findings are genuinely fixed** — I verified empirically against the live guards with a scratch project dir rather than reading the ledger. `ln -s ../<ledger>.md reviews/disputes/link.md` is now blocked (exit 2); writing through an already-existing symlink is blocked by *both* guards; `reviews/disputes/.commit-approved` is blocked by both; `reviews/disputes/../<ledger>.md` is blocked. Legitimate dispute writes still pass in both guards. Suite is green: **445 passed, 2 skipped**. I am not re-reporting either finding.

I also probed the residual symlink surface (`cp -s` instead of `ln`, variable-indirection paths). Those do defeat the carve-out, but only through techniques — CWD changes, `$VAR` path assembly — that defeat every other rule in `bash_guard.py` equally and pre-date this commit, and the file's own docstring scopes it as "hardening against realistic evasion, not a proof." So that suspicion dissolved and I'm not reporting it.

One real defect survived, plus two documentation gaps against the plan.

**Major — the new agent-writable directory sits inside the approval hash's blind spot.** `scripts/review_scope_hash.sh:13` excludes `':(exclude)reviews/*.md'`, and git pathspec `*` matches `/`, so that pattern covers `reviews/disputes/*.md` too — I confirmed this with `git ls-files -- 'reviews/*.md'`, which lists `reviews/disputes/README.md`. That exclusion was safe only because everything under `reviews/` was reviewer-authored and guard-blocked for agents; this commit creates a class of file that is agent-authored *and* invisible to the hash. The consequence chains through three gates: `.githooks/commit-msg:44` uses the same exclusion, so a finalize amend carrying a dispute file looks like it "adds nothing beyond reviews/ ledgers" and a plain subject is accepted; `pre-commit` sees an addition, not an `MDR`, so the append-only rule passes; and `.githooks/pre-push:50-52` recomputes the same excluded hash, matches `.git/.review-approved`, and prints "already approved — skipping re-review." Nothing in `scripts/critical_paths.txt` covers `reviews/`, so the CI label gate doesn't catch it either. The content is not inert: `scripts/agent-review.sh` now instructs every future reviewer to read `reviews/disputes/` and re-judge findings from it, so the unreviewed channel is one that steers later verdicts. The one-line fix is to make the exclusion non-recursive — `':(exclude,glob)reviews/*.md'` — so only top-level ledgers are exempt. Worth noting the diff nowhere mentions the hash, and matrix rows 106-109 don't consider it, so this reads as an unconsidered interaction rather than a decision.

**Minor — the CLAUDE.md reference named in the deliverable was never written.** `workflow-trust-plan.md:2318` states the deliverable includes the checklist "referenced from `CLAUDE.md`", but grepping CLAUDE.md for `WT.12`, `checklist`, and `disputes` returns nothing. Done-when (d) only requires the checklist to exist, which it does, so this doesn't fail a Done-when item — but it has a practical cost. CLAUDE.md is the instruction surface every session actually loads, and its "Commit & review lifecycle" section still says nothing about the dispute channel. The reviewer prompt was updated, so reviewers will look for disputes; the agent that needs to *write* one has no way to learn the channel exists.

**Minor — the as-built section describes a deliverable that isn't in the commit.** `workflow-trust-plan.md:2337` still opens with "Three deliverables" and its first bullet describes `/commit` in the present tense as shipped ("encodes the lifecycle's seven steps"), while the SCOPE note ~40 lines later in the same section says it was dropped and deferred to WT.9. The commit ships two deliverables. A future session reading the as-built as the record of what landed will go looking for `.claude/commands/commit.md` and not find it.
