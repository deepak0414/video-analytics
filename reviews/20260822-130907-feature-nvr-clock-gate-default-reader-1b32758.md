### Minor findings

1. **`src/va/sources/ocr_clock.py:151` — DST fall-back hour maps to fold=0 only, so a correct clip in the repeated local hour reads 3600 s off and is deterministically rejected; under `va watch` that holds the camera watermark until the window rolls off the ring.** `naive.replace(tzinfo=tz).timestamp()` picks the first (DST) instance of an ambiguous wall-clock. Scenario: `VA_NVR_TZ=America/Los_Angeles`, a motion episode at 01:30 on the second pass through 01:xx on fall-back night; the overlay reads `01:30:00 AM`, localizes to the PDT instance (request − 3600), skew 3600 > 600 → `reject`; every retry/phase re-OCRs the same pixels, `watch.py:222-237` holds the watermark and aborts the camera's pass each cycle, so episodes queued behind it can expire (~6 days). Once a year and only if motion occurs then — but the cost is a multi-day camera gap. Safe path: when `tz` yields different epochs for fold 0/1, emit the candidate nearer the other frames' consensus is no help (same ambiguity) — instead give the reader the request (e.g., an optional `hint_epoch` kwarg on `read_head_clock`, defaulted, so the Protocol stays compatible) and pick the fold closest to it, or have the verifier accept a reading if either fold is within tolerance; at minimum document the caveat next to the watermark-hold note.

2. **`COORDINATION.md:~905` — the "VALIDATED on .va-24h's 9806 real OCR rows … end-to-end gate over each video's real head OCR accepts 233/234" claim is not what the shipped reader sees, and nothing reproducible is checked in.** `ocr_results` has no confidence column, and per video only 0–3 rows fall at t<0.5 s (the true 8-frame head at 20 fps spans 0.4 s): the 1-fps Role-10 rows span seconds, so the validation must have used a multi-second proxy head with synthetic confidence — more independent overlays than the near-identical 8 real head frames, so the reported 0-false-reject rate is optimistic for the actual path. Not a block (the parse-robustness numbers are real and the fail-open design is sound), but per "determinism is not correctness": state the method (which rows counted as "head", what confidence was assumed) in the log entry and check the script in (e.g. `scripts/`), or run the shipped `OcrClockReader.read_head_clock` over the real `.va-24h` clip files and report that count.

Not reported after verification: the coarse 600 s tolerance doesn't flip `test_nvr_contamination.py`'s injected-reader tests (7-day skews); conftest's `VA_NVR_CLOCK_GATE=off` is overridden explicitly by the wiring tests and doesn't touch the opt-in test (which calls `RapidOcrFrameOcr` directly); an invalid `VA_NVR_TZ` already fails at `resolve()` via `nvr._tz()`, so the reader's unguarded `ZoneInfo` adds no new failure; a 7-foreign+1-aligned head now rejects where dHash alone trimmed — fail-closed on one clean frame, acceptable and outside the census 1–5-frame band; `need_agent_review:` subject is exempt from the wording rule.
