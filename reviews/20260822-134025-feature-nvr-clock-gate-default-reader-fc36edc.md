## Review: `fc36edc` — default OCR burned-in-clock reader for the NVR delivery verifier

Scope read: the full range diff (`ocr_clock.py`, `nvr.py`, `verify.py`, `conftest.py`, both test files, the validation script, CLAUDE.md, COORDINATION.md) plus `verify.py`'s gate logic, `rapidocr_inproc.py`, `media/frames.py`, `sources/base.py`, `pipeline/manage.py` (reingest), `pipeline/watch.py`, and the two prior review rounds on this branch. Both prior rounds' findings (`\d{2}` parse, keep-every-≥2-cluster consensus, dHash+clock combination test, `RUN_OCR_CLOCK` doc, DST fold hint, checked-in `--real` validation script) are addressed on the merits in this commit. I could not execute pytest (not approved in this sandbox), so the suite's green state is the author's claim, not mine. I did run one read-only query against `.va-24h/catalog.db` to check the validation claim.

### MAJOR 1 — the 8-frame head inspection (0.4 s @ 20 fps) is shorter than the same-camera wrong-week heads the new reader now detects, so clips with a GOOD body are REJECTED whole rather than trimmed; the "ZERO false-rejects of good footage" validation never looked at the body
`src/va/sources/nvr.py:138` (`HEAD_FRAMES = 8`) + `COORDINATION.md:913`. `_head_trim` rejects when foreign runs to the end of the inspected frames. The reader now makes the 8 inspected frames visible to the clock gate, and the `--real` run reports 26 rejects "all genuine wrong-week heads". The script records head OCR only (`run_real` → `rejects.append((vid[:8], [str(clip)]))`), so it cannot tell a wholly-wrong-week clip from a ~0.5–1 s stale head on a correct body. I checked the proxy data: of 234 `.va-24h` clips, **17 have every Role-10 row at t<0.5 s ~7 days off, and 16 of those 17 have ALIGNED bodies at t≥1 s** (shipped `parse_lorex_clock`/`_to_epoch`, LA tz, 600 s tol). Those are recoverable clips the verifier's own design says should TRIM (the census repair was "drop t<1 s rows", i.e. head-confined); with only 0.4 s inspected they fail closed. Live consequence: each such pull burns `MAX_TRIES` re-pulls + the exact-window fallback (re-OCR-ing the same overlay if the lead-in repeats), and if the head repeats the window is "unpullable" and `va watch` holds the camera's watermark (the exact stall the DST test docstring calls multi-day). **Safe path:** size the inspected head to the observed band (≥ ~1 s at the channel's fps — e.g. `HEAD_FRAMES` derived from `probe().fps`, or let the clock reader read head frames up to ~1.5 s) so a long stale head TRIMS at its aligned tail; and make the validation honest — have `run_real` also OCR a frame at t≈1–2 s per reject and report "head-off/body-aligned (trimmable but rejected)" vs "whole-clip wrong-week" separately, then restate the COORDINATION/CLAUDE.md claim from that split.

### MAJOR 2 — `va reingest` on an existing workdir now destroys and fails these clips; COORDINATION says the reader "gates FUTURE pulls, not a re-pull of that data", which is false
`COORDINATION.md:919`; mechanism in `src/va/sources/nvr.py:285-314` + `src/va/pipeline/manage.py:128-145`. `reingest` = `remove_video(keep_media=True)` (role rows/dir gone) → parks the preserved clip in `cache/` → `ingest` → `fetch()` finds the cache file and **re-verifies it with the now auto-on reader** → for the ~17–26 `.va-24h` clips above: `DeliveryRejected` → `os.replace(out, aside)` (bytes renamed to `.rejected.mp4` in the *transient* cache dir) → `_pull_window` → ring expired → `RuntimeError` → row `failed`. Before this commit the same reingest succeeded (dHash passes a same-camera head). Net: on the user's primary backfill workdir, `va reingest <one of those clips>` now drops all its role data, leaves a failed row, and hides the bytes under a name nothing reuses — and the log entry tells the next session it's safe. **Safe path:** correct the COORDINATION/CLAUDE.md text (fetch() re-verifies cache — CLAUDE.md already says so), and make the cache-reverify path non-destructive on failure: if the re-pull after a set-aside raises, restore `aside → out` before propagating (bytes stay where reingest parked them), and/or pre-flight-refuse in `reingest` for nvr clips that fail verification, mirroring the quarantine refusal that runs BEFORE `remove_video`. At minimum document "`va reingest` on `.va-24h` needs `VA_NVR_CLOCK_GATE=off` for these clips".

### MINOR 3 — `CLOCK_OCR_TOL_S = 600 s` leaves any consistent single-digit minute/hour substitution as a deterministic false-reject → watcher stall; the census foreign floor is 12 h
`src/va/sources/nvr.py:149`. The `\d{2}` fix removed the dropped-digit class, but the commit's own argument (RapidOCR errs the SAME way across the near-identical head) applies equally to substitutions: `09:35` read as `09:55` on all 8 frames = 20 min > 600 s → confident, agreeing, foreign-to-the-end → reject; every retry re-OCRs the same pixels → RuntimeError → watermark hold. Unmeasured in the sample (the 19 >600 s rows are consistent with the genuine heads), so minor. Safe path: the docs lean on the census "|Δ| ≥ 12 h foreign band" — set the OCR-path tolerance at (or the foreign floor near) that band; it still catches wrong-day/wrong-week and tolerates any single time-field substitution. (`test_readings_are_localized_with_the_nvr_timezone`'s mis-tz→reject assertion would need adjusting.)

### MINOR 4 — the fail-open branches for a broken OCR backend are untested
`src/va/sources/ocr_clock.py:268-273` (`RapidOcrFrameOcr` disable-on-exception) and `:312-313` (per-frame `except`). Fail-open is THE policy of this change, but only the missing-file path (`test_reader_never_raises_when_head_frames_cannot_be_decoded`) is covered; a fake `FrameOcr` that raises would pin that a crashing OCR engine yields `()` (accept) rather than a failed pull. Safe path: one test with a raising fake through `NvrRecordedSource._verify_and_trim` asserting the clip is returned unchanged.

Verified and not reported: `hint_epoch` threading (Protocol default, nvr.py call, both test doubles, script) is consistent; `_to_epoch` fold selection honours the hint with both tz-given and system-local paths; `RapidOCRReader(None)` is safe (`load = load or {}`); `first_frames` yields PIL images matching `_read_frame`; `_AUTO_READER` keeps `base.resolve_source()`/web/watch signature-compatible; conftest's `VA_NVR_CLOCK_GATE=off` makes every bare `NvrRecordedSource()` in the suite model-free, and the wiring tests override it explicitly; `default_timestamp_reader` honours the runtime `importlib.util.find_spec` patch; `VA_NVR_CLOCK_GATE`, `RUN_OCR_CLOCK` and the script are documented in CLAUDE.md + COORDINATION.md; no `critical_paths.txt` entry touched; `need_agent_review:` subject exempt from the wording rule.
