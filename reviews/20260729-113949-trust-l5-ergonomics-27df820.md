Review complete. The full offline suite is green (441 passed, 2 skipped), the new tests genuinely exercise both guards including the `..` traversal, the `/commit` doc's claims match the actual hook behavior (pre-push hash skip verified against `.githooks/pre-push:51-55`), and `reviews/disputes/` contains no rebuttals to re-judge. Two real defects survived verification, both confirmed empirically against the live guard scripts:

**1. Major — symlink staging defeats the "verdict ledgers stay untouchable" guarantee.** The new carve-out makes `reviews/disputes/` agent-writable, and `ln` symlink creation with a relative target that never lexically mentions `reviews` slips both the carve-out and the ledger rule. I verified both commands are ALLOWED by `bash_guard.py`:

```
ln -s ../20260727-x.md reviews/disputes/link.md   → allowed (link target "../20260727-x.md" has no "reviews" segment)
echo forged > reviews/disputes/link.md            → allowed (target is carved out) — the write lands on reviews/20260727-x.md
```

The same write-through works via the Write tool past `path_guard.py`, which normalizes lexically and never resolves symlinks. This is squarely in the guard's own scope — `ln -sf /bin/true .venv/bin/pytest` is already in `BLOCKED_COMMANDS` because symlink attacks were considered, and WT.11's Done-when (b) ("still cannot create, edit or delete a verdict ledger") plus matrix row 107 ("blocked in BOTH guards") are not actually met. A hardlink is caught (both `ln` operands are treated as write targets); only the symlink form leaks, because the link's *source* text is what's checked, not what it resolves to.

**2. Minor — the two guards diverge on sentinel-named files inside `reviews/disputes/`.** In `path_guard.py` the carve-out (`sys.exit(0)` at line 60-61) runs *before* the `STATE_BASENAMES` basename check, so `Write reviews/disputes/.commit-approved` is allowed; `bash_guard.py` checks `ps[-1] in SENTINELS` *before* its carve-out, so `touch` of the same path is blocked (both verified). No live bypass — sentinels are only consumed at repo root and `.git/` — but this is precisely the "parallel implementations disagree" defect the commit's own as-built note names as a lesson, and no test pins either behavior. Moving the path_guard carve-out below the basename check restores agreement.

Everything else checked out: the `normpath` change in `norm()` introduces no regressions I could construct (`..`-traversal to sentinels, `~` handling, and rule-3 delete paths all behave), `rm -r reviews/disputes` and `mv` out of disputes stay blocked, the docstring correction accurately narrows the overclaim, and the WT.12 checklist lists all four recurring defects with their originating rounds.
