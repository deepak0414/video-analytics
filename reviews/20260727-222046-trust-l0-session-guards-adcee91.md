## Full review

I probed the guards empirically with the committed hook scripts (feeding them PreToolUse-style payloads) rather than reasoning from the regexes alone. Three of the blocks they claim to enforce are reachable around.

## Findings

**1. (major) `.claude/hooks/bash_guard.py:126` — a quoted destination refspec evades force-push-to-main entirely.** `_dst()` strips `+` and `refs/heads/`, but not shell quotes, so the destination token compares as `"main"` rather than `main`. Verified against the committed guard: `git push --force origin "main"` → exit 0 (allowed), `git push -f origin 'main'` → exit 0, while the unquoted control `git push --force origin main` → exit 2. This is precisely the quoted-value class the plan records as fixed for override tokens (`AGENT_REVIEW="skip"`), and there is no layer behind this one — pre-push has no force detection and WT.5 CI does not exist yet, so remote main gets rewritten.

**2. (major) `.claude/hooks/bash_guard.py:43-63` — the always-enforced rules use a strictly weaker verb list than `WRITE_VERBS`, so ordinary write utilities reach every protected artifact.** `WRITE_VERBS` (used only for the machinery rule) includes `sed -i`, `dd`, `ln`, `truncate`, `chmod`; the `reviews/`, `.review-approved`, `.stop-gate-green` and pytest rules each hand-roll a shorter subset. Verified allowed: `sed -i s/request_changes/approve/ reviews/20260727-x.md`, `dd if=/tmp/h of=.git/.review-approved`, `dd of=.git/.stop-gate-green if=/tmp/h`, `ln -sf /tmp/forged.md reviews/x.md`, `ln -sf /bin/true .venv/bin/pytest` — while the control `sed -i s/x/y/ .claude/hooks/bash_guard.py` blocks correctly. Concretely: the current round's ledger is *untracked*, so the pre-commit/pre-push append-only gates (`--diff-filter=MDR`) never see it as modified; `sed -i` flips its verdict to `approve` and the human's digest is a forgery. Separately, `dd of=.git/.review-approved` with the scope hash makes pre-push (`.githooks/pre-push:45`) skip the backstop review, and `ln -sf /bin/true .venv/bin/pytest` neuters both the Stop gate and pre-push Gate 1. This is not the acknowledged "arbitrary shell / inline python" residual — these are the same plain write verbs the file already enumerates one section above.

**3. (major) `.claude/hooks/path_guard.py:25` — `ALWAYS_PROTECTED` omits `.git/.stop-gate-green` and `.venv/bin/pytest`, so file tools bypass the protection bash_guard tries to give them.** Verified: path_guard returns 0 for both paths (and 2 for `.git/.review-approved`, `reviews/`). A single `Write` of a `#!/bin/sh\nexit 0` stub over `.venv/bin/pytest` (mode preserved, `.venv` is gitignored so no git gate sees it) makes every test gate pass on a red suite; a `Write` of the computed cache key to `.git/.stop-gate-green` ends the turn without running pytest. Validation-matrix row 44 asserts both are blocked; via file tools they are not.

**4. (minor) `.claude/hooks/stop_gate.sh:13` — the state path is hardcoded `.git/.stop-gate-green`, contradicting the plan's as-built claim.** `workflow-trust-plan.md` round-4 notes say "the state file resolves `git rev-parse --git-dir` (linked worktrees)"; the committed script does not. In a linked worktree `.git` is a file, so the write fails silently (no `set -e`) and the full offline suite re-runs at every Stop. Behaviorally minor, but the plan records a fix that did not land.

**5. (minor) `tests/test_trust_guards.py:38` — the tables still mirror the regexes for the variants above.** `BLOCKED_COMMANDS` covers clustered/reordered/`git -c`-prefixed forms and the `>`/`tee`/`cp` write verbs, but no quoted refspec and no `sed -i`/`dd`/`ln` against `reviews/`, `.review-approved`, `.stop-gate-green`, or the pytest binary — the same "tables mirror the regexes, not the invariants" root cause the plan says was addressed. `BLOCKED_PATHS` likewise omits the two paths in finding 3.

Verified and dropped: the `-n` cluster rule does not false-positive on `--amend`, `--dry-run`, or message text; `GITCMD` correctly restores the global-flag anchors from the last round; absolute-path traversal (`…/foo/../.claude/x`) is normalized and blocked (and Edit/Write requires absolute paths, so the relative-path gap is unreachable); `--force-with-lease` to feature branches is allowed; the multi-line/multi-push segment handling still blocks; the reviewer timeout raise (480→900s) is documented with its background-push caveat; no existing tests were deleted or weakened; the CLAUDE.md and COORDINATION.md entries are present and accurate.

Also outside the findings: a live `.guard-override` sentinel is still in the working tree — it should be removed before this branch is finalized, or every subsequent session runs with the machinery guards relaxed.
