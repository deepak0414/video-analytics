**What holds up:**

- **Reprocess wiring (7feee60):** rows-first/restamp-second holds on every failure path; the zero-decoded-frames guard counts frames, not detections; the removed-mid-run re-check sits immediately before the destructive writes; the tracker gate exactly mirrors ingest's `_enabled` tolerance for an absent role; the executor's disabled-skip runs before the `satisfied` check so a profile-disabled tracker is never restamped via the new `_SATISFIES` edge; the fps fallback is null-safe against the fps-NULL restamp a never-stamped first reprocess produces. The five tests genuinely construct their scenarios (including a real config-dir overlay for the disabled-tracker cell and a mid-run `remove_video` injected through the tracker). CLAUDE.md and COORDINATION.md were updated in the same change, and the two finalized commit subjects are plainly descriptive.
- **Degradation surfacing (c7cae95):** the warn fires from the same `failed`/`skipped` sets the roles maintain, hits the app logger independent of `VA_TRACE` (the condition that hid the .va-24h gap), and intentional skips stay trace-only info. Both tests assert observable behavior.
- **Adapter prime-once/re-prime (40d4830):** the marker on the shared model is correct across per-video adapter instances, live validation is recorded, and a doubly-failed prime propagates into ingest's best-effort guard. No query-time `detect()` call sites exist, so no vocab-thrash path today.

**What does not hold up — the head commit (7ab3e90), the one this review gates:**

Its entire content is "free the evicted model before rebuild", and the freeing demonstrably does not happen. The recovery (`self._model = None` → `MANAGER.unload` → `MANAGER.get`) runs **inside** the `except Exception as e:` block, and the live exception's traceback holds the `set_classes` frame whose `self` **is** the old model — so the old weights remain strongly reachable through `unload()`'s `gc.collect()`/`empty_cache()` and through the replacement build. Both copies are resident during the rebuild, which is exactly the double-residency the commit message, the code comment, and the prior review's finding say this change eliminates. I verified this empirically: a `weakref` to the model stays alive at the rebuild point in the shipped shape, and is collected when the recovery is hoisted out of the `except` block (flag pattern: catch → log → set `rebuild=True`; do drop/unload/rebuild/re-prime after the `try/except`). That is the smallest fix.

The covering test passes on the broken code because it asserts a proxy — `det._model is None` at unload time — rather than the behavior its own docstring claims ("the old weights are collectable before the replacement loads"). Per the repo's decoration-test lesson, it should take a `weakref.ref` to model #1 and assert it is dead inside the unload spy (after a `gc.collect()`); that assertion fails on the shipped code and would have caught this.

The two suspicions I chased that dissolved: a stale `_va_primed_classes` marker on an evicted model could mislead a second live adapter, but no concurrent-adapter path exists in ingest/reprocess/serve; and the fps-NULL restamp after a never-stamped detector reprocess is explicitly handled by the null-safe fallback.

Verdict: **request_changes** — the head commit's sole deliverable is not delivered and its test cannot detect that.
