## Review: `origin/main..HEAD` (WT.3 session guards)

**The headline: this commit's tree is byte-identical to `d69bde1`, which the previous review round already rejected.** `git diff --quiet d69bde1 HEAD` reports no difference. The fixes for that round's five major findings *do* exist — I found them in `.claude/hooks/bash_guard.py`, `path_guard.py`, and `stop_gate.sh` in the working tree, and they look correct — but they are **uncommitted**. The commit under review still contains the vulnerable versions.

This matters concretely because of how the repo's own lifecycle works. `scripts/review_scope_hash.sh:13` hashes `git diff origin/main <commit>` — committed content only. And the documented finalize step in CLAUDE.md is `git add reviews/ && git commit --amend`, which stages only `reviews/` and so would leave the guard fixes behind. Approve-and-finalize from here ships the pre-fix guards with a ledger that reads "fixed."

Below are the defects as they exist in the committed code. I verified each by reading the regexes rather than executing them, because the *live* (fixed) guard on disk correctly blocks the probe commands — which is itself confirmation that the on-disk version differs from the committed one.

**`git commit -nm` skips every commit gate** (`bash_guard.py:23`). The rule is `\bgit\s+commit\b[^|;&\n]*\s-n\b`. Against `-nm`, the trailing `\b` needs a boundary between `n` and `m`; both are word characters, so there is none and the match fails. That one command bypasses the branch guard, secret scan, test-deletion guard, and the commit-msg lifecycle. (The working-tree fix, `\s-[a-zA-Z]*n`, handles it.)

**Gate machinery is writable from Bash** (`bash_guard.py:43`). `path_guard.py` runs only on the `Edit|Write` matcher, and the committed `RULES` list has write-verb protection for `reviews/` and the three sentinels but nothing for `.githooks/`, `.claude/`, or the trust scripts. `echo 'exit 0' > .githooks/pre-push` matches no rule. Since `scripts/setup-hooks.sh:6` sets `core.hooksPath .githooks` — a working-tree path — an *uncommitted* one-line write disables L1 and L2 instantly, and there is no layer behind it: `.github/` does not exist, so WT.5's CI is not built. This defeats WT.3 goal (d) outright.

**The Stop gate's cache goes stale on commit** (`stop_gate.sh:14`). The key hashes `git diff HEAD -- src tests pyproject.toml` plus `git status --porcelain -- src tests` — working-tree dirtiness with no reference to the commit sha. Every clean tree therefore produces the same hash. Run green once on a clean tree, break a test (turn now blocks), then commit the broken code as `wip:` — the tree is clean again, the cache hits, pytest never runs, and the turn ends on a red suite. That is the `wip:`/`checkpoint:` flow CLAUDE.md documents, not an evasion.

**Force-push to main is blocked in only one word order** (`bash_guard.py:25`). The pattern requires `--force`/`-f` to appear *before* `main`, so `git push origin main --force` and `git push origin main -f` pass. This is exactly the flag-reordering evasion (claude-code #40117) that the plan's own design note at `workflow-trust-plan.md:383` cites as the reason these regexes exist as the enforcement layer.

**Quoting defeats the human-only override tokens** (`bash_guard.py:29`, identically 31/33/35). The rules match literal `AGENT_REVIEW=skip`, so `AGENT_REVIEW="skip" git push` passes the guard; the shell strips the quotes and `agent-review.sh:28` sees `skip`, writes a WAIVED ledger, and exits 0. The agent waives its own pre-push review — and that line's own comment says the waiver becomes human-only "by mechanism once WT.3's session guards land," which is this PR.

On tests: nothing was deleted or weakened, but `tests/test_trust_guards.py` is **unchanged in the working tree too**. I traced every entry in `BLOCKED_COMMANDS` and `ALLOWED_COMMANDS` against the fixed on-disk regexes, and all 57 tests pass identically against both the vulnerable and the repaired guards. The tables enumerate the spellings the regexes already match rather than the invariants, so they have zero regression value for the very fixes they should be locking in. `test_stop_gate_green_then_cached:451` never commits, so it structurally cannot catch the cache-staleness bug. Against WT.3's "Done when" (each L0 matrix row demonstrated) and WT.9's (every **A** row passes offline), rows 9, 10, and 11 hold only in their literal command form.

Two smaller items. Raising the reviewer timeout to 900 s (`agent-review.sh:79`) exceeds the 600 s Bash-tool ceiling on the *synchronous* pre-push backstop at `.githooks/pre-push:48`; the plan's justification at `workflow-trust-plan.md:649` ("commits that trigger reviews run as background jobs") covers only the post-commit path. It fails closed, so this is a wasted-work issue rather than a hole. And `.claude/settings.local.json` is newly gitignored by this diff but absent from `path_guard`'s `PROTECTED` list while its sibling `settings.json` is protected — the working-tree fix closes this by protecting all of `.claude/`.

The one thing that is genuinely fixed and committed is PR 2's round-5 carry: writes to `.git/.review-approved` and fabricated `reviews/*.md` ledgers are blocked by both guards.

**The fix is likely mechanical**: stage the three modified guard scripts into the amend, and extend the test tables to cover the evasion variants rather than the spellings.
