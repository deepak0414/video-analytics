**Findings — two minor, none blocking.**

1. **`scripts/check_critical_paths.sh:31` (minor)** — the justification for the replay is factually inverted. With `--name-status`, a `git mv` is caught whether or not rename detection runs: when inexact detection is *skipped*, the pair is never formed and the diff reports `D<TAB>old` plus `A<TAB>new`, so the old path is still in the scanned list (this is also why `test_rename_of_a_critical_file_is_caught` would pass with no `-M` at all — `-M` changes the output *format*, not the coverage). The companion clause is imprecise the same way: the hazard is folding stderr into the *command substitution*, not "routing it to stdout" — the script's stdout is never re-parsed. The implemented behavior is correct either way; the problem is that this premise is now recorded in the open-flake ledger (`workflow-trust-plan.md`, the "what changed" paragraph), the test docstring, and the commit body. Safe path: state it as "a warning must not enter `$raw`, where it would be scanned as a path (it cannot mask a real one — extra lines can only add spurious matches)", and drop the "the only reason a `git mv` is caught" clause from all four copies before the finalize amend.

2. **`tests/test_trust_guards.py:699` (minor)** — `assert "warning:" not in res.stdout` cannot detect the failure mode its docstring names ("folded into stdout it would be parsed as a changed path"). The checker never echoes anything from `changed`; `ok:`/`FAIL:` lines print the table *pattern*. Under the buggy `2>&1` variant the warning would land in `$raw` and still never reach stdout, so this assertion passes on the broken code — the working guard is the preceding `warning: in res.stderr` / `git: ` pair. The "must not enter the path list" half is therefore unguarded, and by CLAUDE.md's 2026-08-08 lesson that reads as covered when it isn't. Safe path: reword the docstring to claim what the assertion actually pins (the replay stays off the gate's stdout report), or state in the test that the path-list half is unobservable through the CLI surface.
