### Findings

**1. MAJOR — `.claude/hooks/bash_guard.py:321` — the carve-out's anti-link defense misses hardlinks created by coreutils `link`, and unlike symlinks, the write-through end cannot catch them.**
The creation-side rule fires only when `command_name(seg)[0] == "ln"` (or `cp` with a `-s` spelling), and `link` is not in `WRITE_CMDS`, so `link reviews/<ledger>.md reviews/disputes/hl.md` produces zero write targets and passes the guard entirely (`/usr/bin/link` is present on this box). The containment that kept earlier link findings minor then structurally fails: both guards' carve-out checks use `os.path.realpath`, which resolves symlinks but is blind to hardlinks — the hardlink's path *is* `reviews/disputes/hl.md`, inside `allowed_root`, so `is_always_protected` returns False and both `echo … > reviews/disputes/hl.md` and a `Write` through path_guard are allowed, truncating the shared inode and rewriting the ledger. Round 5's ledger says "hardlink … blocks too", but the spelling probed there was `ln` (caught because any `ln` mentioning `reviews/disputes` blocks); `link` was never probed, and round 6 dismissed only cwd-relative evasions. This violates Done-when (b) and matrix rows 107/108 ("blocked at BOTH ends"), and WT.12 item 7 — added in this very commit — explicitly names hardlinks.
*Scenario:* post-commit review writes the current round's `request_changes` ledger (untracked until finalize). Agent runs `link reviews/<that-ledger>.md reviews/disputes/hl.md` (allowed), then `echo '# Agent review — approve' > reviews/disputes/hl.md` (allowed) — the ledger now reads approve. The digest shown to the human comes from the forged file; at finalize `git add reviews/` stages it as **Added**, so the append-only MDR gates (pre-commit 2c, pre-push 2b) never fire, and the scope hash excludes `reviews/*.md` — the forged verdict ships end-to-end.

**2. MINOR — `.githooks/pre-commit:30` — the guards and the append-only exclusions disagree on carve-out depth, recreating round 6's false-block one directory deeper.**
Both guards admit dispute paths at any depth (`len(ps) > i + 2` / `len(_ps) > 2` — `reviews/disputes/sub/x.md` is writable), but the new exclusions in pre-commit 2c and pre-push Gate 2b use `:(glob,exclude)reviews/disputes/*`, and with glob magic `*` does not cross `/` — a nested dispute file is *not* excluded. Fail-closed and off-convention (README specifies flat `<ledger-basename>.md`), hence minor, but it is exactly the mechanism-divergence class this PR's as-built note warns about ("one change per mechanism").
*Scenario:* an agent organizes disputes as `reviews/disputes/<pr>/finding.md` (guards allow it, so nothing signals the convention), commits it, and a re-review asks for stronger evidence; the edit-and-amend fails with "reviews/ ledgers are append-only … ALLOW_LEDGER_EDIT=1" — the human-only-override pressure round 6's minor was fixed to remove.
