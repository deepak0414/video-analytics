## Findings

**1. CRITICAL — `src/va/sources/nvr.py:380-396` — a new lighting mode can never be seeded in production, so the headline regression ("backfill works at night/any lighting") is only fixed for channels first seen in that lighting.**
`accepts()` returns ok only when the channel library is empty or the consensus is within 18 bits of an existing entry. On rejection `_pull_window` raises at line 381 before ever reaching `refs.add` at line 396; on acceptance, `add()` dedups anything within 18 and returns. Net: the library holds **exactly one entry per channel, forever** — the multi-mode accumulation the class docstring, CLAUDE.md ("FIRST pull per channel per scene (e.g. day vs IR) seeds the library"), and the warning text ("seed deliberately — one pull per camera per lighting mode") all describe is unreachable code. `MAX_PER_CHANNEL = 12` can never be exceeded. Concrete failure: seed ch1 with a daytime pull (the normal first use), then backfill last night's motion episodes — every pull raises `"does not match any known scene … closest 38 > 18"`, which is the same night-rejection failure this commit exists to remove, now unrecoverable without hand-deleting `nvr_refs/ch1.json` (which discards the day entry, flipping the problem to daytime). Safe path: give per-scene seeding a real production path — e.g. an explicit seed command/flag, or a policy decision (flagged to the human, since auto-accepting an unknown scene weakens the wrong-camera check) — and make CLAUDE.md match what ships.

**2. MAJOR — `tests/test_nvr_source.py:649-665` — the regression test constructs a state production cannot reach, so it passes against the broken behavior.**
`test_a_night_version_of_the_same_scene_still_verifies` builds the two-mode library by calling `lib.add(1, night)` directly, with the comment "a night pull seeds its mode" — but in production a night pull on a day-seeded channel raises before `add` is reachable (finding 1). The suite is green while the shipped `_pull_window` flow rejects exactly this scenario. This is the CLAUDE.md 2026-08-08 lesson verbatim: a test that never constructs its scenario is decoration. Safe path: exercise the night-after-day case through `_pull_window` (with `_fetch_window`/`_frame_hashes` stubbed) and make it fail on the current code first.

**3. MAJOR — `src/va/sources/nvr.py:478` — the all-zeros sentinel is a *plausible real hash*: it equals the dhash of any dark/uniform frame, so undecodable frames can sit inside a "clean" run and can even become the consensus.**
`dhash` of a black frame is all-zeros (no gradients), so on dark footage — precisely the night scenario this change targets — the consensus is at or near zeros and a torn/truncated frame's sentinel scores distance ~0, i.e. *clean*. The old code's `10**6` sentinel guaranteed "an unverified frame must never sit inside a run judged clean"; the new docstring still claims that invariant, but the code no longer holds it. Worse, if sentinels are the majority (disk-full truncating every JPEG, mass decode failure), `consensus_hash` becomes all-zeros, the entire undecodable pull is judged internally consistent and ingested, and on a first-sight channel the library is seeded with the zero hash — permanently rejecting all real footage afterward. Also `len(hashes) < 3` at line 364 counts sentinels as "decodable frames", so the guard doesn't guard. Safe path: keep a validity mask — exclude invalid frames from `consensus_hash`, force their self-distance to an impossible value (the old `10**6`), and count only valid frames against the `< 3` floor.

**4. MAJOR — `src/va/sources/nvr.py:396` — the library is seeded before the pull passes its own verification, so a failed first pull permanently poisons the channel.**
`refs.add(chan, cons)` runs before the clean-run check (line 400) and the trim encode (line 416). On a first-sight channel, a pull that then fails "no clean run of at least 1.0s" (internally inconsistent footage, heavy contamination, mass-torn frames per finding 3) has already written its garbage consensus as the channel's only reference. Every subsequent good pull is then rejected with "does not match any known scene" until someone hand-deletes the JSON — a silent, persistent failure born from a transient one. Safe path: move `refs.add` after the trim succeeds (after `os.replace`), and seed from the clean run's frames rather than the whole-window consensus.
