**What holds up.** The core change is correct and the reasoning behind it is right: capturing git's stderr to a file rather than folding it in with `2>&1` genuinely protects `$raw` from being polluted by a success-path warning, and the `trap … EXIT` is set after the early `table` exit so nothing leaks. `test_unreachable_base_reports_gits_own_error` is a real regression test, not decoration — against the old code `res.stdout` contains neither `"git said"` nor `"fatal:"` (git's stderr went to `res.stderr`), so it fails on the pre-change script. The fixture's new `assert res.returncode == 0` breaks no existing call site: I checked every `cp_repo` user (lines 599–697) and every `change()`/`git_mv()` path writes distinct content, so no `git commit` can legitimately return "nothing to commit". `gc.auto=0` is honored (repo-local config, and the checker runs with `cwd=work`). No test was deleted or weakened. The mktemp-fails edge case fails *closed*, so it is not a gate hole. The commit body's honest-scope paragraph is exactly right under the repo's "determinism is not correctness" rule — it presents the gc hypothesis as a removed candidate, not a fix.

Two notes, not findings: this PR touches `scripts/`, so the `critical-paths` gate will demand `human-reviewed` — that label is the human's to apply in the GitHub UI. And the `need_agent_review:` subject is exempt from the commit-clarity rule; its body is already self-sufficient for the finalize amend (no plan-ID shorthand to strip).

**Findings — three minor, no critical or major.**

1. **`scripts/check_critical_paths.sh:32`** — on the success path git's stderr is now written to a temp file that is deleted unread, so warnings that previously reached the CI log are silently dropped. This is the same "git's words discarded" failure the commit exists to fix, just moved to the other branch. Safe path: emit it to the script's own stderr (`[ -s "$_cp_err" ] && sed 's/^/git: /' "$_cp_err" >&2`) — stderr can never enter `$raw`, so the 2>&1 hazard the comment describes stays closed.

2. **`scripts/check_critical_paths.sh:35`** — the retained hint asserts the one cause the commit body itself establishes as inapplicable: `pr-gates.yml:44` pins `fetch-depth: 0`, so a shallow checkout cannot be the reason in the only automated caller. Safe path: name what the checker actually needs ("the base sha must exist in this checkout — a force-pushed base branch or a shallow clone removes it") or drop the line; git's real message now carries the diagnosis.

3. **`workflow-trust-plan.md:1922`** — every prior correction to this checker got a WT.7 as-built note (PR 4; the two backstop rounds), and the plan header instructs sessions to read those notes first; this change and its flake evidence exist only in a commit-message body. Safe path: a short WT.7 as-built entry recording the behavior change, the eliminated candidates (fetch-depth, gc.auto, 30 non-reproducing local runs), and that the root cause is still open.

**Verdict: approve** — nothing here blocks merge; all three are worth folding in before the finalize amend.
