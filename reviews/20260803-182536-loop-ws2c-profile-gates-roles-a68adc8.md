## Full review

Review complete. The suite is genuinely green (553 passed / 2 skipped, matching COORDINATION's claim), and this round's headline is that all seven findings from the previous review of this branch (2b6ccd3) were actually fixed in the follow-up commit — I verified each in the diff: `embedder_id(cfg)` and `index_text(cfg)` now tag shards from the pinned overlay config, `va stale`/`va reprocess` compare and restamp per recorded profile via `config_for()`, skipped roles purge prior rows, the diarizer gate order is fixed (with a regression test), footage profiles ship in all four config dirs, and the carried-over shape validation got the tests reproducing the original failing inputs. Documentation and COORDINATION parity are thorough.

What remains:

**Major — `_enabled()` lets a best-effort role's gate abort the whole ingest.** `src/va/pipeline/ingest.py:202` calls `cfg.role(role)` directly, which raises `KeyError` for any role absent from roles.yaml. Every registry getter deliberately tolerates that shape (`except KeyError` → stub fallback, "so ingest works without explicit configuration" — and `embedder_id`'s own docstring leans on that contract). I reproduced it: a `VA_CONFIG_DIR` roles.yaml listing only `visual_embedder` previously ingested fine on stubs; now `_enabled("vlm_captioner")` raises before any role runs, the inner handler marks the video FAILED, and nothing (not even visual embedding) happens. That is exactly the "best-effort role able to abort ingest" class. Safe path: `spec = cfg.roles.get(role)` and treat a missing role as enabled (mirroring the `r in cfg.roles` guard `stale_report._current` already uses).

**Minor — `object_tracker`'s `enabled` flag is silently ignored.** Every other best-effort role is gated, but line 394 runs the tracker whenever the detector produced detections; a profile with `object_tracker: {enabled: false}` (detector on) still tracks, writes `object_tracks` rows, and provenance-stamps the role — contradicting the unconditional "`enabled: false` skips a best-effort role" claim in CLAUDE.md/COORDINATION. Extra data, not wrong data, and no shipped profile hits it, hence minor. Safe path: gate on `_enabled("object_tracker")` (with the same purge-on-skip) or document the tracker as detector-coupled.

**Minor — the WS2.c "uses the overridden vocab" done-when is only pinned at the config layer.** `test_profile_vocab_reaches_the_ingest_classes` asserts `get_ingest_classes(load_config(...))`, but no test fails if ingest drops the `cfg` argument from `get_ingest_classes(cfg)`/`get_ingest_actions(cfg)` (the security ingest test doesn't assert detections). This exact seam already broke silently once in this change — the new CLAUDE.md lesson about zero-arg lambda doubles is its epitaph. Safe path: one e2e ingest under a stub profile whose `classes:` are color names, asserting the detected labels.

**Minor — a profile that overrides an embedder produces shards the query path can never search.** The tag is now honest (prior finding 1 fixed), but `va query`/`va transcript` load base config, so shards tagged with a profile's embedder are permanently TAG-3-skipped (warn + fewer results — safe direction, but the video silently never matches). `test_embedder_id_honors_the_profile_overlay` legitimizes embedder overrides without this caveat appearing anywhere. Safe path: a sentence in CLAUDE.md/COORDINATION ("embedder overrides in a footage profile make those videos invisible to the profile-unaware query path until query grows profile awareness"), or an ingest-time warning.

Commit subjects are all provisional `need_agent_review:` — exempt from the clarity rule. Schema v3 is migrated and logged; no contract breaks found.

Verdict: **request_changes** — one major, and it's a five-line fix in `_enabled()` plus (optionally) the tracker gate in the same pass.
