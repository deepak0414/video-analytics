## Full review

Review complete. The suite is genuinely green (547 passed / 2 skipped, matching COORDINATION's claim), the WS2.a/b/c "Done when" items each have real tests, and the documentation parity is good (flags, config keys, and the web-agent behavior note all landed in the same change). The commits are provisional `need_agent_review:` subjects, which are exempt from the clarity rule.

However, the WS2.c claim that "the pin is passed to EVERY role getter" is not true for the embedder identity paths, and that opens three real holes, all in the per-ingest `--profile` combination that this change ships:

**Major findings**

1. **Shard embedder tag ignores the pinned profile config** — `embedder_id()` (src/va/registry.py:353) self-loads the base config, but ingest embeds with the overlay config (`get_visual_embedder(cfg)`, then tags at src/va/pipeline/ingest.py:357). A footage profile that overrides `visual_embedder.model` — the exact overlay shape WS2.a's own test demonstrates — produces a shard whose vectors are SigLIP but whose tag says `hash`. The TAG-3 guard then skips that shard under *both* configs (dim mismatch under base, tag mismatch under the profile), so the video silently vanishes from visual search everywhere, with only a log warning whose suggested remedy (reprocess) re-embeds under base and silently reverts the profile. Safe path: give `embedder_id` an optional `cfg` parameter and pass ingest's pinned cfg.

2. **`index_text` never receives the pinned config** — src/va/pipeline/ingest.py:390 calls it bare, so `get_text_embedder()` self-loads without the per-ingest profile; a profile's `text_embedder` override silently does not apply, while `_record_provenance` stamps the role with the overlay fingerprint (a model that didn't run). It errs toward false-stale, but the override is a silent no-op and the COORDINATION claim ("the stamp records what the roles really ran under") is false for this role. Safe path: pass the pinned cfg (embedder + tag) into `index_text`.

3. **`va stale` / `va reprocess` are profile-unaware** — stale.py:37 and reprocess.py:311 fingerprint against `load_config()` with no knowledge of `videos.profile`. Every video ingested under `--profile security` reads permanently stale for its overridden roles (skipped speech roles *and* the classes-fingerprinted detector), and the loop is unclearable: the pointed-to remedy `va reingest` correctly carries the profile forward, re-producing the same stamp. Worse, for a profile overriding a reprocess-wired role (embedders/captioner), `va reprocess --all-stale --yes` rebuilds that role's data under the **base** config — silently stripping the profile's overrides while restamping the video clean. The skipped-roles-read-stale choice is documented as deliberate, but its permanence and the reprocess-reverts-overrides mutation are not. Safe path: make `stale_report`/reprocess resolve each video's recorded profile when fingerprinting (or explicitly exclude profile-disabled roles), and log the gap in COORDINATION.

**Minor findings**

4. **Diarizer-disabled corner stamps a skipped role** — at src/va/pipeline/ingest.py:244, `if lines and _enabled("speaker_diarizer")` short-circuits: STT enabled + empty transcript + a profile disabling only the diarizer leaves the disabled role neither skipped nor failed, so it gets provenance-stamped, violating the documented "skipped roles are never stamped" invariant. Fix: evaluate `_enabled("speaker_diarizer") and lines` (order swapped).

5. **Skipped roles don't clear prior rows** — a role gated off never calls its `replace_*`. Retrying a previously-failed ingest (which wrote transcripts before dying) with `--profile security` leaves the old transcript rows live, and `index_text` then indexes them — a "no-speech-by-design" video with searchable transcript text, contradicting the behavior note given to the web agent. Safe path: a disabled role should still purge its table (replace with empty).

6. **`security` profile unusable from the real-model config dirs** — `security.yaml` exists only in `config/`; `run-siglip`/`run-claude`/`run-qwen3vl` have no `profiles/footage/` dir, so the flagship combination `VA_CONFIG_DIR=run-siglip/config va ingest --profile security` fails with FileNotFoundError. It fails loudly, so minor — but the shipped profile can't run where security footage would actually be processed. Safe path: ship the footage dir into the run-* config dirs (or fall back to the repo config for footage profiles) and note it in CLAUDE.md.

7. **Carried-over shape validation has no regression test** — the WS2.a review carry-over (top-level `roles:` as a list crashed with a bare AttributeError) was fixed at src/va/configuration.py:224–229, but no test feeds it `roles: [...]` or a top-level list document; `test_non_dict_role_override_raises` covers a different shape. Per the repo's own lesson, the regression test should reproduce the original failing input.

Verdict: **request_changes** — the three majors share one root (the pinned overlay config doesn't reach the embedder-identity and stale/reprocess machinery), so a single follow-up pass over `embedder_id`/`index_text`/`stale_report` closes most of this.
