## Full review

All prior round-6 findings are genuinely fixed in this HEAD, and the round-4 dispute stands independently confirmed by the round-6 ledger, so I re-judged nothing stale. My probes against the committed guard found four new defects — all in the interaction between the two round-6 additions (heredoc skipping and `bash -c` recursion), each verified by executing the committed guard.

## Findings

**1. MAJOR — the `bash -c` recursion scan ignores the heredoc filter, so a heredoc body containing `bash -c '<loop>'` is false-blocked** (`.claude/hooks/bash_guard.py:450`). The main loop-scan skips heredoc bodies as data (lines 373–385, row 120's guarantee), but the recursion scan rebuilds its token stream from scratch — `_flat = [t for line in _split_lines_outside_quotes(text) for t in _tokenize(line)]` — with no heredoc handling. Verified: `cat > w.sh <<'HEOF'` + `bash -c 'until ! pgrep -f job.py; do sleep 5; done'` + `HEOF` is **BLOCKED**, while the plain-loop heredoc (the shipped test fixture) is allowed. The heredoc body is data being written to a file; blocking it re-introduces the exact false-block class round 6's major fixed, one scan over. This is also the fifth instance of the project's tracked meta-defect: row 120 asserts "heredoc bodies are DATA" as a guarantee, and the code provides it for only one of the two scans. No test covers the combination.

**2. minor — the `bash -c` payload scan crosses command-separator boundaries, attributing another command's `-c` to bash** (`.claude/hooks/bash_guard.py:454`). `_args = _flat[_j + 1:]` runs to the end of the whole command, past `&&`/`;`/`|`. Verified: `bash setup.sh && grep -c 'until ! pgrep -f job.py; do sleep 5; done' notes.txt` is **BLOCKED** — grep's `-c` (count) is read as bash's `-c`, and grep's *data* pattern is recursed into as a shell payload. A quoted loop being searched for in a file is prose, not an action — the fourth recurrence of that class.

**3. minor — quote-state leakage across heredoc bodies lets a real self-observing loop escape** (`.claude/hooks/bash_guard.py:373`). `_split_lines_outside_quotes` runs before the heredoc filter and tracks quotes through body text, so an apostrophe in a heredoc body (`don't` in a comment — extremely common) opens a phantom single-quote that swallows the terminator line and everything after it. Verified: heredoc with `don't` in the body followed by a genuine `until ! pgrep -f job.py` loop *after* the `EOF` is **allowed**; the identical command without the apostrophe is blocked. Bypass-direction, but it silently disables the guard on the accident path it exists for.

**4. minor — the heredoc-opener regex matches herestrings and `<<` inside quoted strings, skipping real commands as "body"** (`.claude/hooks/bash_guard.py:381`). The regex matches inside `<<< EOF` (herestring) and inside `echo "a << b"`; both then treat following lines as heredoc data. Verified: both spellings followed by a real self-observing loop on the next line are **allowed**. Same bypass direction as #3.
